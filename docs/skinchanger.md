# Скинченджер

## Предметы
- Список строится из `items_game` и иконок `panorama/images/econ/default_generated`: показываются только пары «оружие + скин», для которых в игре есть иконка, то есть реально существующие.
- Добавленный предмет создаётся как `CEconItem` в локальном SOC-кэше инвентаря.

## Лоадаут без подмены оружия
Перед экипировкой читается текущий предмет слота (`CCSPlayerInventory`, vfunc 8 = GetItemInLoadout).
- В слоте то же оружие (или дефолт): экипируем, исходный ID запоминаем.
- В слоте другое оружие (M4A4 вместо M4A1-S, R8 вместо Deagle): лоадаут не трогаем, в лог пишется предупреждение. Скин виден, когда держишь это оружие.
- При снятии экипировки и при выгрузке возвращается исходный предмет слота.

## Отрисовка скина
1. В `C_EconItemView` оружия пишутся def, itemID, account, quality.
2. Дополнительно пишутся fallback-поля `m_nFallbackPaintKit/Seed/Wear/StatTrak`. В режиме «Fallback fields» (Skins → Options) ставится `m_iItemIDHigh = -1`, и материал строится из этих полей без SOC.
3. Модель, маска legacy (2 — старая модель, 1 — новая), перегенерация композита оружия и клона в руках (`m_hViewmodelAttachment`). Новый клон, создаваемый при доставании оружия, обрабатывается заново.

## Нож
- Native animations: настоящая vdata ножа загружается из `weapons.vdata`, затем в `m_nSubclassID` пишется токен ножа и вызывается `OnSubclassIDChanged`. Игра сама находит vdata и пересобирает анимграф, поэтому при сетевых апдейтах нож не откатывается.
- При выгрузке возвращается исходный `m_nSubclassID`.
- После подмены ставится `m_bAttachmentDirty`, чтобы игра пересобрала клон.

## Диагностика
Skins → Options → Diagnostics: def, itemID, paint, fallback paint, legacy, маски оружия и клона, число перегенераций и модель оружия в руках. Если скин не виден, пришли скрин этого блока.
