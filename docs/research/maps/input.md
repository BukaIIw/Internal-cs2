## Summary
CURRENT ARCHITECTURE (all on the game main thread, split-screen slot 0 only):

1) Install (movement.cpp:477-502, called from hooks.cpp:271): RTTI vtable ".?AVCCSGOInput@@" -> vtable[5] = CreateMove; pattern "GetUserCmd"; pattern "MergeSubtick"; pattern "GetAimPunch"; convars sv_airaccelerate, sv_air_max_wishspeed, sv_gravity, sv_maxspeed, sv_subtick_movement_view_angles. Three MinHook detours: GetUserCmd, MergeSubtick, CreateMove (MH_EnableHook is done elsewhere). movement::installed=true only if all three succeed.

2) hkCreateMove(input, slot, active) (movement.cpp:455-474): slot!=0 -> passthrough. Publishes events::CreateMove(0, input) under SEH (SafeMisc 443-453; any exception sets misc::thirdperson=false). Subscribers: misc::OnCreateMove (thirdperson, wiring.cpp:175-178) and Spread's OnCreateMove (stores CCSGOInput* for input-history reads, spread.cpp:59-62). If no movement/aim/rage/jumpcheck feature on -> passthrough. Else: SafeSample(&current) (pawn state), captured=nullptr, activeThread=GetCurrentThreadId(), call original, activeThread=0. If a cmd was captured by hkGetUserCmd during the original, SafeCmd -> ragebot::OnCmd(cmd) and, if it returns true, calls CCSGOInput vtable[6](input, cmd) (purpose unknown, see facts).

3) hkMerge(input, slot) (movement.cpp:412-433) = the "subtick merge" function that builds the per-tick subtick::Input buffer at CCSGOInput+0x228 (+slot*0x928). It runs INSIDE the original CreateMove (gated by activeThread == current thread and slot==0). Before calling original: saves in->forward/in->left (previous tick analog = "last movement impulses") and reads int at input+0xB50 ("frames"). After original: if frames>0, latches realHeld=(down|pressed)&IN_JUMP, realKeys=(down|pressed)&move-keys, realSpeed=down&IN_SPEED. Re-samples pawn state, then SafeEdit -> Edit: Bunnyhop or (if bhop inactive) JumpCheck::Run; then SubtickStrafe (strafeMode==1 && sv_subtick_movement_view_angles!=0) or Autostrafe (analog). Then aim::OnInput and ragebot::OnInput mutate the same Input buffer (rotate angles, inject click). The game then converts this buffer into the protobuf usercmd, so ALL movement/aim editing today happens on the pre-protobuf CCSGOInput buffer, not on CSubtickMoveStep protobufs.

4) hkGetUserCmd(controller, sequence) (435-441): records the FIRST cmd returned during our CreateMove into `captured`. That CUserCmd is edited post-hoc by ragebot::OnCmd (silent aim + attack) via usercmd.cpp.

VIEW ANGLES: read from Input->pitch/yaw (CCSGOInput+0x688/+0x68C). Written for visible aim by rotating Input pitch/yaw AND every event pitch/yaw by the same delta (aim.cpp:353-363 delta-based; ragebot.cpp:437-447 absolute target -> delta), then game::SetViewAngles(input, pitch, yaw) = native fn(input, 0, float[3]{p,y,0}) (game.cpp:714-721). Silent aim (ragebot only): pre-cmd stage only records pendingPitch/Yaw/pendingFire (ragebot.cpp:497-505); post-CreateMove usercmd::SetAngles writes Base->viewangles and every input_history entry's view_angles (clamp pitch +-89, normalize yaw, z=0, has|=3) and rotates Base forward/left by (oldYaw-newYaw) to keep movement direction; then vtable[6] is called.

ATTACK INJECTION: two paths. (a) pre-cmd, Input buffer: Click() in aim.cpp:342-351 / ragebot.cpp:426-435: if IN_ATTACK already in down -> nothing; else remove existing attack events, insert press at when=0 and release at when=0.5, set pressed|=1 and released|=1 (down not set => tap inside one tick). (b) post-cmd, protobuf: usercmd::Attack (usercmd.cpp:36-55): CInButtonState value|=1, changed|=1; base->buttonstate buttonstate1|=1, buttonstate2|=1, has|=3, base has|=1<<1; if attack1_start_history_index<0 and history non-empty -> set to 0 and has|=1<<5. Attacking() = (value|changed)&1 || base buttonstate1&1.

MOVEMENT ALGORITHMS:
- Sample (79-106): local controller -> m_hPlayerPawn -> pawn; valid iff health>0 and m_MoveType==2 (WALK). ground = m_fFlags&1; velocity = m_vecAbsVelocity; z = sceneNode m_vecAbsOrigin.z; gravityScale (sanitized to (0,10]); maxSpeed = CPlayer_MovementServices::m_flMaxspeed (sanitized (1,1000) else 250); aim punch via native GetAimPunch(aimPunchServices, float[3], true).
- Bunnyhop (132-163): if bhop bind active and jump physically held: remove all IN_JUMP events, clear pressed/released jump bits. On ground: Press(when=0). In air: landing = JumpCheck::LandingFraction (if Ready and no previous fault); if 0<=landing<1 and vz<=0: Press(min(landing+0.02, 0.98)). Otherwise: if we had jump down last tick, insert release at 0; clear down jump; jumpSent=false. Press(): if jumpSent, insert release at 0 and released|=jump, when=max(when,1/64); insert press at `when`, pressed|=jump, down|=jump, jumpSent=true.
- JumpCheck (jumpcheck.cpp): "subtick jump" (single perfectly timed jump) when bhop is not active; same press/release logic as Bunnyhop with when = landing fraction (min 1/64 after a release). LandingFraction: on ground -> 0 (and remembers z); rising -> -1; else ground Z = highest hit of 5 vertical LINE traces (centre + 4 corners at +-15u) from z+2 down to z-256 with mask 0x1001, falling back to last remembered ground z; solves 0.5*g*t^2 - vz*t - h = 0 with g = sv_gravity*gravityScale, frac = t/(1/64) - lead; returns -1 if frac>1, clamps <0 to 0. Reads modern-jump schema fields only for debug display.
- Autostrafe "Analog" (strafeMode 0, 180-242): in air with jump held. Clears move key bits and move-button events, zeroes analog of existing analog events, inserts 16 analog events at when=i/16. For each: target = viewYaw + DirectionOffset(realKeys) (left +90, right -90, with forward halved, with back 180-side/2); if speed>=10: theta = acos(c) with half = sv_airaccelerate*maxSpeed*(1/64/16)*0.5, c = cap/(2*speed) if half>=cap else (cap-half)/speed, cap = sv_air_max_wishspeed; wish = velYaw +-theta toward target (|delta|>2) else alternating side. Movement: rel = wish-view, forward=cos(rel), left=-sin(rel); event analog = new - previous (deltas). Simulates accel (gain = min(half, cap - v.wish)). Final in->forward/left = last values.
- SubtickStrafe "Subtick yaw" (strafeMode 1, default, 244-329): requires sv_subtick_movement_view_angles != 0 and IN_SPEED not held. Forces down = IN_FORWARD only, forward=1, left=0, clears move events and analog. ticks = clamp(32-count,1,32); dt=1/64/ticks; gain = airaccel*maxSpeed*dt; cap=min(air_max_wishspeed, maxSpeed); per step ideal = min(acos((cap-gain)/speed), 90); yaw = velYaw+ideal if (|delta|>170 && speed>80) || delta>0 else velYaw-ideal; when = floor(i*64/ticks)/64; last step yaw = real view (restore). Velocity sim uses CS2 two-half accel (half; rest). Inserts events with absolute yaw, then reassigns EVERY event's yaw to the yaw of the step active at its `when`.
- Third person (misc.cpp): CameraThink(input, slot) detour: when wanted, force input+0x229 (bInThirdPerson)=true, write cam_idealdist value = misc::thirdDistance, temporarily set sv_cheats value byte to 1 around the original, restore, re-force 0x229. misc::OnCreateMove toggles: on enable copies view pitch/yaw (input+0x688/0x68C) into camera offset input+0x230/0x234 and 30.f into input+0x238; writes input+0x229=want, input+0x6A8=0 and calls pawn vfunc index 315 (byte offset 0x9D8) with bool want; re-calls it when the pawn pointer changes. Cleanup on unload restores.

THREADING/SAFETY: Everything runs inside the client CreateMove call on the main thread; activeThread ensures Merge/GetUserCmd hooks only act inside our CreateMove. SEH: Edit faults in stage 4 (jumpcheck) disable JumpCheck permanently, other faults disable bhop+autostrafe permanently; Cmd faults disable ragebot; Misc faults disable thirdperson; Sample faults yield invalid state.

REF EXAMPLES (owner's target style): operate AFTER the cmd exists on systems::input::usercmd (CUserCmd: .buttons CInButtonState and .csgo_user_cmd CSGOUserCmdPB), appending CSubtickMoveStep protobufs via systems::g_input.acquire_subtick_step and editing base forwardmove/leftmove/viewangles, using prediction pre-state rather than live entity reads, and hull traces with the player-movement filter.
