5) icons (src/icons.cpp) - async icon textures for the menu: request queue (LIFO) -> worker thread (COM/WIC) -> vpk::Read -> own VTEX_c decoder (DATA block, extra-data type 4 compressed mip sizes, LZ4 decoder, picks the largest mip <=256 px wide, formats 1=BC1, 2=BC3, 16=PNG via WIC, 28=BGRA8; RGBA images halved down to <=160 px with premultiplied box filter) -> render thread uploads at most 24 per frame as IMMUTABLE 1-mip textures -> cache keyed by path, LRU eviction when >400 entries down to 300 (only entries unused for >2 frames). icons::Get(path) returns SRV or 0 and enqueues.

6) vpk (src/vpk.cpp) - own VPK v2 directory reader limited to panorama/images/econ/*, scripts/items, resource; handles preload bytes and archive index 0x7FFF (data in _dir.vpk at dataOffset); mutex protected Read.

WHY IT WORKS BADLY (root causes): (a) the whole in-match path depends on the game resolving our fake SOC item by m_iItemID from the client inventory cache; in a live match the server re-networks C_EconItemView fields so they are constantly reverted -> 'changed' fires again -> model refresh/regenerate every 250 ms -> flicker/reverts; (b) ~12 unsigned hardcoded vtable indices (72, 69, 8, 0, 2, 1, 3, 27, 6, 14, 199, holder 3) for inventory/SO-cache/schema; (c) knife subclass token computed from the item code string instead of the def-index string used by the owner's reference, so native mode usually fails and it falls back to SetModel-only (wrong animations, reverts), plus a hand-rolled internal VData loader; (d) gloves get no paint attributes on the item view; (e) mesh-group/legacy handling targets m_hViewmodelAttachment and only forces mask 1 if it was 2; (f) agent change has no bounds/attachment fix; (g) Sync on every frame stage; (h) pointer-keyed caches and time throttles.

## Defects
- [high] In-match skins rely on the game resolving a fake SOC CEconItem by m_iItemID; the server re-networks C_EconItemView fields, so they revert and ApplyWeapon sees 'changed' again, which refreshes the model and regenerates it every 250 ms. This causes flicker, reverts and skins that never apply. (src/skins.cpp:426-521, 368-379) fix: Switch to the reference fallback path: faux id 0xF0000000/0x10, fallback fields, composite rebuild once per change, with state keyed by handle and settings revision.
- [high] The knife subclass token is hashed from the item class name. The owner's reference hashes the decimal def-index string, so the native mode usually fails and the code falls back to SetModel only (wrong animations, reverts on update). (src/skins.cpp:441-452; src/game.cpp:549-576) fix: Use murmur2_lower(to_string(def), 0x31415926), then OnSubclassIDChanged, then SetModel(weapon_get_model_path(iv)), as in ref/knives.cpp:256-268.
