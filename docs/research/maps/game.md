## Summary
HOW IT WORKS TODAY
1) There is NO SchemaSystem usage anywhere. grep for SchemaSystem/schemasystem returns nothing. The only CreateInterface call in the codebase is mem::Interface("client.dll","Source2Client002") (hooks.cpp:264), and it is used only to log a note. Every netvar offset (game::Offsets, game.h:7-24) is scraped out of client.dll .text code bytes. A byte signature finds an instruction that touches the field, and the disp32 (size 4) or disp8 (size 1) at a fixed position is read as the offset (game.cpp:47-53 Field()). src/features/schema.{h,cpp} is misnamed: schema::Field/schema::Code are the same byte-scrape helper, parameterised by module name (schema.cpp:4-16). They are used by hitbox.cpp:86-93 (client.dll + animationsystem.dll) and jumpcheck.cpp:54-58.
2) game::Init (game.cpp:79-290) runs on the hook-install thread. hooks.cpp:247 retries it up to 50 times with Sleep(200). Order: load client.dll (mem::Load, PE section table), then 36 REQUIRED field sigs (any miss aborts Init with Fail(name)), then 33 OPTIONAL field sigs (a miss leaves 0), then ViewMatrix, the armor/itemServices/hasHelmet combo sig, SetViewAngles, EntityList (required), CEconItem::CreateInstance (required), SetDynamicAttributeValue<uint32/float> (U32 required), CreateBaseTypeCache (required), GetItemSchema (required), SetModel / SetMeshGroupMask / OnSubclassIDChanged (required), AttachmentComposite (optional), VDataLoader (optional), VDataRegistry (optional), RegenerateWeaponSkins (updateComposite required), and RTTI lookups for CCSInventoryManager (required) and CSchemaAttributeType_String (optional). The result is a global ready flag plus an error string (game::Ready/Error).
3) Pattern engine. mem::FindAll/Find (mem.cpp:47-80) does a linear memchr scan of a module's .text only, with '?'/'??' wildcards. core/patterns.cpp wraps it. patterns::Find takes the first hit with no uniqueness check (it registers matches=-1). patterns::FindAll registers the count. patterns::FindRef resolves RIP-relative refs and returns null unless all hits resolve to the same target. patterns::Note records non-sig addresses (vtables, globals, convars, iface) for the menu's pattern list. A background worker can verify sigs or regenerate them from the on-disk client.dll with hde64 (patterns.cpp Build: <=40 instructions, <=96 bytes, masks rel/imm and RIP disp, and with looseOffsets also every disp32).
4) Entity access. entityList is the RIP target of "48 8B 0D ? ? ? ? 48 85 C9 74 ? 41 83 F8 FE" (game.cpp:181). Identity(i) (game.cpp:55-64) does chunks=*(u8***)entityList; chunk=chunks[i>>9]; identity=chunk+(i&0x1FF)*0x70. CEntityIdentity layout: +0x00 entity instance ptr, +0x10 uint32 EHandle, +0x20 const char* designer name. Handle(h) (game.cpp:302-310): reject 0xFFFFFFFF, index=h&0x7FFF, require identity+0x10==h (full serial check), return identity+0. EntityAt(i,&designer) and HandleAt(i) read the same slots. LocalController (game.cpp:312-328) linearly scans indices 1..64 for designer=="cs_player_controller" && bool at off.isLocalController. As a side effect it caches localIndex, which LocalIndex() returns.
5) Rendering helpers. ViewMatrix is a float[16] global (row-major). visuals.cpp:34-44 Project uses w=m[12..15]·v, x=m[0..3]·v, y=m[4..7]·v and rejects w<0.01. Bone (game.cpp:685-697) reads node=pawn+sceneNode; bones=*(u8**)(node+modelState+0x80); pos=*(Vec3*)(bones+i*0x20) for i in 0..127, and accepts it only if within 200 units of node+absOrigin. EyePosition (game.cpp:699-712) is absOrigin + (0,0,z), where z=float at pawn+viewOffset+viewOffsetZ if in (10,80), else 64. SpottedBy (game.cpp:723-730) reads uint32 mask[2] at pawn+spottedState+spottedMask, bit=(controllerIndex-1). It returns true (fail-open) if the offsets are missing.
6) Input. SetViewAngles(input,pitch,yaw) calls fn(CCSGOInput*, int slot=0, const float[3]{pitch,yaw,0}) (game.cpp:714-721). input is the CCSGOInput* that movement.cpp:411 hkMerge (MergeSubtick hook) passes to aim::OnInput and ragebot::OnInput.
7) ConVars. FindConVar (game.cpp:513-543) brute-forces client.dll. It finds a NUL-preceded exact string in .rdata, then the first 'lea rdx,[rip+str]' (48 8D 15) in .text, then the first 'lea rcx,[rip+obj]' (48 8D 0D) within 0x90 bytes. That obj is the static ConVarRef in client.dll. Value = *(u8**)(obj+8) + 0x58 (game.cpp:545-555). Used for sv_gravity, sv_jump_precision_enable (jumpcheck.cpp:51-52), sv_cheats, cam_idealdist (misc.cpp:54-55), sv_airaccelerate, sv_air_max_wishspeed, sv_maxspeed and sv_subtick_movement_view_angles (movement.cpp:488-492). Bool convars are read or written as a byte at the same value pointer (misc.cpp:29-37 temporarily writes sv_cheats=1 around CameraThink).
8) Inventory/econ (used only by skins.cpp). CCSInventoryManager is the global object found via RTTI vtable ".?AVCCSInventoryManager@@" plus a .data scan for the first qword equal to that vtable (an in-place static object, not a pointer). vfunc 72 = GetLocalInventory, 69 = EquipItemInLoadout(team,slot,u64 itemId). CCSPlayerInventory: +0x10 SOID{u64 id,u32 type,u32 pad}, +0x68 shared object cache; vfunc 8 = GetItemInLoadout(team,slot) -> C_EconItemView*; vfunc 0 / vfunc 2 = SO created / destroyed notify (owner SOID*, item, 4). CreateBaseTypeCache(cache, 1) -> type cache: +0x8 int count, +0x10 CSharedObject** array; vfunc 1 = AddObject(item)->bool, vfunc 3 = RemoveObject(item). Items come from CEconItem::CreateInstance (alloc 0x48). Attributes: GetItemSchema() vfunc 27 = GetAttributeDefinition(index). SetDynamicAttributeValue<uint32> and <float> are called back-to-back with the same bits. String attrs: def+0x18 = ISchemaAttributeType*; if its vptr equals the CSchemaAttributeType_String vtable, call type vfunc 6 (item, def, const char*).
9) Model/VData (skins.cpp, hands.cpp). SetModel(entity,const char*). Skeleton = sceneNode vfunc 14. ModelName = *(const char**)(skel+modelState+modelName). MeshGroupMask = u64 at skel+modelState+meshGroupMask; SetMeshGroupMask(skel,mask) is called only if it differs. OnSubclassIDChanged(entity). Composite regen: clearComposite(weapon+compositeOffset,true) then updateComposite(weapon,false). Viewmodel regen goes through the AttachmentComposite sig. VData: global registry, findVData(registry,-1,token), loadVData. A KV3 walk loads knife VData on demand (KnifeVData, game.cpp:626-647). Token() = lowercase MurmurHash2, seed 0x31415926 (CUtlStringToken).
10) Item database (items.cpp/vpk.cpp/kv.cpp) does not touch game memory. hooks.cpp:278 starts std::thread(items::Load). It derives <client.dll dir>/../../../pak01_dir.vpk (game/csgo/pak01_dir.vpk), parses the VPK v1/v2 directory (keeping only panorama/images/econ/*, scripts/items, resource) and reads scripts/items/items_game.txt. A custom KeyValues1 text parser (in-place unescape, [$cond] skipping, // comments, case-insensitive keys) builds the items, paint kits, sticker kits and prefab-chain resolution. Available skins per weapon come from the file names in panorama/images/econ/default_generated (<itemcode>_<paintcode>_light_png.vtex_c). Names are localized from resource/csgo_english.txt and csgo_russian.txt (lang/Tokens). Publication is via std::atomic<int> items::state (0 loading, 1 ok, -1 error); menu.cpp checks state before reading. vpk stays open after load; icons.cpp:287 calls vpk::Read from the render thread (protected by vpk's mutex).
11) vecmath.h is header-only math on game::Vec3: Basis/Forward (Source convention: forward={cp*cy,cp*sy,-sp}, right={sy,-cy,0}, up={sp*cy,sp*sy,cp}), Angles(dir) (pitch=-atan2(z,hyp)), NormalizeYaw to [-180,180), and quaternion Rotate(q xyzw, v).
THREADING: game::* is called from the render/Present thread (visuals, menu), the CreateMove/MergeSubtick thread (aim, ragebot, movement), FrameStageNotify (skins, glow, hands) and the loader thread (items). None of it is synchronized. localIndex and KnifeVData's static tried[] are written from multiple threads.
CALL SITES: Handle/LocalController are used by 11 files. EntityAt by glow, visuals, hands, aim, ragebot, visibility. Bone by visuals, aim, ragebot, visibility. EyePosition by visuals, aim, ragebot, visibility. SetViewAngles by aim, ragebot. SpottedBy by visibility. ViewMatrix by visuals. Inventory/econ/model/VData functions by skins.cpp only. CurrentVData by spread.cpp, damage.cpp. HasVData and VData have no callers.
