## Summary

HOOK FLOW AND THREADING (movement.cpp)
1. hkCreateMove (CCSGOInput vtable[5], movement.cpp:455). For slot 0 it publishes events::CreateMove(input). spread.cpp:61 uses this to remember the CCSGOInput* for reading input history. If bhop, strafe, rage, aim or jumpcheck is on, it samples local state (Sample(): velocity, flags, aim punch through GetAimPunch(services, out, true), movement.cpp:79-106). It then sets activeThread and calls the original.
2. Inside the original, the game calls:
   - MergeSubtick, hooked as hkMerge (movement.cpp:412). The subtick Input lives at CCSGOInput+0x228 and the frame count at +0xB50. After oMerge the hook runs, in this order: SafeSample, then movement Edit (bhop, jumpcheck, subtick strafe/autostrafe, which rewrites event yaws), then aim::OnInput (legit and trigger), then ragebot::OnInput (movement.cpp:427-432).
   - GetUserCmd, hooked as hkGetUserCmd (movement.cpp:435). It captures the FIRST cmd returned on this thread.
3. After the original returns, SafeCmd (movement.cpp:382) runs ragebot::OnCmd(captured). If that returns true, it calls CCSGOInput vfunc 6 (mem::Call<void,6>(input, raw)). Nothing documents what vfunc 6 does.
4. ragebot::OnFrameStage and visibility::OnFrameStage run on FrameStage stage==7 (wiring.cpp:156/161, hooks.cpp:92 publishes after the original). Both FrameStage and CreateMove are assumed to run on the main thread. Shared globals (tracks, frameTime, localHandle) have no synchronisation.
5. Init order is in wiring.cpp:236-247: ray::Init, Hitboxes::Init, Spread::Init, damage::Init. Each one degrades gracefully: no ray means radar spotted mask, no hitboxes means bones, and so on.

RAGEBOT (ragebot.cpp)
- Run (449-506) is called from Merge.
  - Local pawn and active weapon come from weaponServices->activeWeapon. Gun() means the item category is <= items::Heavy.
  - damage::Read caches the weapon VData.
  - eye = game::EyePosition: scene-node absOrigin + m_vecViewOffset.z (clamped 10..80, fallback 64).
  - bullet angles = in->pitch/yaw + punch.
  - lead = Lead() (331-337) = (QPC now - time of the last FrameStage 7, clamped 0..0.1 s) + extraTicks/64.
- Target selection:
  - Locked() (339-357) rescans only the locked handle. After lockTicks consecutive failures (default 12) the handle is cleared.
  - Otherwise Acquire() (359-401) loops controllers 1..64 (designer "cs_player_controller", skips local) and filters with Valid() (84-99): health>0, lifeState==0, team unless aim::teammates, scene node present and not dormant, m_bGunGameImmunity false.
  - FOV is measured to bone 6 (head), falling back to origin. Results go through insertion sort by FOV and only the best kMaxScan=4 are Scanned.
- Scan (275-329):
  - Hitboxes::Collect, falling back to BoneBoxes (241-273: hardcoded capsules bone6-6 head r4.5, 5-6 neck r3.5, 4-5 chest r6, 2-4 and 0-2 stomach r6).
  - Every box is shifted by velocity*lead (Velocity(): EMA of FrameStage origin deltas, falling back to m_vecAbsVelocity).
  - Enabled groups are sorted by Priority (head>neck>body>limbs, or body first when preferBody).
  - Per box: a damage prefilter at (dist to center - radius), then points from CapsulePoints (157-199) or BoxPoints (201-239) at scale = clamp(groupScale*pointScale/0.8, 0, 0.95).
  - Per point: damage check, then visibility::Point (two traces). The FIRST passing point wins. There is no best-damage or best-point scoring and no penetration.
- Fire decision (483-491):
  - p = target.pitch - punch.x, y = target.yaw - punch.y.
  - fire = autofire && CanFire (116-126: clip1>0, weapon m_nNextPrimaryAttackTick <= controller m_nTickBase) && Accurate (403-424).
  - Accurate: when silent and NoSpread is enabled, NoSpread::Apply rewrites p/y; then Spread::Allow (hitchance or exact-seed check).
  - Click() (426-435) inserts subtick events into the merge Input: attack pressed at when=0.0 and released at when=0.5, and sets the pressed|released bits. It does nothing if attack is already down.
- Non-silent (493-497): Rotate() shifts in->pitch/yaw and every event by the delta, then game::SetViewAngles(input, 0, angles).
- Silent (499-505): stores pending{fire,p,y}. After CreateMove, OnCmd (587-597):
  - usercmd::Attack (usercmd.cpp:36-55) ORs IN_ATTACK into cmd->buttons.value/changed and base->buttons state1/state2, sets has bits, and sets attack1=0 when it was <0.
  - usercmd::SetAngles (usercmd.cpp:66-87) writes base->viewangles and EVERY input history entry's view_angles (has&1) to the same angle.
  - It then rotates base forward/left by (oldYaw - newYaw).
  - Subtick moves are not touched and the CRC is not recomputed unless vfunc 6 does that, which is unknown.

LEGIT AIM AND TRIGGER (aim.cpp)
- Best() (123-156): for every valid enemy, collects Hitboxes::Points for the selected hitbox (falling back to bones {6},{5},{4,2} or all of {6,5,4,2,0}). It keeps the minimum-FOV visible point, and visibility::Point traces every point.
- Smoothing: Rotate(delta/smooth) applied per Merge, so it is per tick and not per frame, followed by SetViewAngles.
- RCS: aims at target - punch and measures FOV from view+punch.
- Trigger (322-340): one kMaskShot trace of 8192u along view+punch.
  - If the hit entity is a valid enemy pawn, TriggerHit does analytic ray-vs-capsule/OBB tests (CapsuleEntry/SphereEntry/BoxEntry, 208-275) to find the nearest hitgroup and checks the damage requirement.
  - Fallback without rays: Best(...,3,30) with fov <= atan2(4,dist).
  - The delay uses GetTickCount64. Click is the same as ragebot. There is no hitchance or spread check.

DAMAGE (damage.cpp)
- VData fields come from schema-registration patterns ("C7 44 24 40 <name-hash> 4C 8D 86 <disp32>", disp at +11).
- Formula:
  - dmg = damage * rangeModifier^(dist/500); returns 0 if dist > range.
  - head x m_flHeadshotMultiplier, stomach x1.25, legs x0.75, others x1.
  - Armor: head needs a helmet, legs are never armored, everything else is. health part = dmg*armorRatio*0.5. armor part = (dmg-health)*0.5, capped at armor (then health = dmg - armor/0.5).
  - Required = min(health, minDamage).
- Missing: penetration, the team-specific mp_damage_scale_* convars, heavy armor, and pellet count.

HITBOXES (hitbox.cpp)
- GetHitboxSet(pawn, 0) returns a CHitBoxSet. Its m_HitBoxes CUtlVector has the count at setList and data at setList+8, with element size boxSize (all taken from an animationsystem.dll pattern).
- For each CHitBox:
  - bone = CModel::GetBoneIndexForHitbox(model, hb, 0). model = *(*(modelState+m_hModel)).
  - Bone transform from the skeleton bone array at modelState+boneArray, stride 32: pos at +0, quat xyzw at +0x10.
  - a = pos + q*mins, b = pos + q*maxs, center = mid. capsule if radius>0. axes = q*unit vectors (OBB).
- No transform scale is applied. Bones are the rendered (interpolated) bone cache at Merge time.

SPREAD AND HITCHANCE (spread.cpp)
- Weapon read: inaccuracy/spread via weapon vtable indices taken from the call-site pattern, called as (weapon, nullptr, nullptr) and (weapon). Also reads weaponMode, recoilIndex, VData numBullets and range.
- Chance mode: stratified pseudo-random (xorshift) samples, count = samples clamped 16..512.
  - Revolver alt-fire uses 1 - r^2. Negev with recoilIndex < 3 squares r repeatedly. Both are CS:GO-faithful.
  - dir = f + right*x + up*y with Source basis.
  - Hit = any hitbox via Hitboxes::HitAny (capsule segment distance or OBB slab). Allow if hit% >= minChance (default 65).
- Exact mode:
  - seed = SpreadSeed(nullptr, {pitch,yaw,0}, tick).
  - tick = Spread::Tick: player tick of the CCSGOInput input-history entry at the attack1 index (else the last entry), read during Merge; fallback is the controller tickBase.
  - CalcSpread(def, bullets, mode, seed+1, inacc, spread, recoilIndex, xs, ys). Fires if at least 1 pellet hits a box.

NOSPREAD (nospread.cpp:28-81)
- Assumes the seed depends on angles quantised to 0.5-degree buckets.
- For each (pitch,yaw) bucket within atan(inacc+spread)+1 degrees (max 12), it computes the seed at the bucket centre and the first pellet offset.
- It fixed-point iterates (3 steps) the aim angle so that aim+punch+spread lands on the target, keeps candidates that stay inside the same bucket, and picks the minimum angular error.
- Only used when silent.

VISIBILITY AND RAY (visibility.cpp, ray.cpp)
- ray::Trace calls CGamePhysicsQueryInterface::TraceShape(mgr, ray[0x40 zeroed = line], &start, &end, &filter, trace[0x200]) with a hand-built 0x48-byte CTraceFilter. It reads entity at +0x8, endpos at +0x84 and fraction at +0xAC.
- ray::Clear:
  - World trace (mask 0x1001): blocked if it stops more than 2u short.
  - Shot trace (mask 0x1C300B) to the point +16u: OK if it hits the target, OR hits nothing (fraction>=1), OR is not blocked by another live player and lands within 8u of the point.
- visibility::OnFrameStage caches per-player visibility (any hitbox centre clear) for ESP and glow. visibility::Point falls back to the radar m_bSpottedByMask when rays are unavailable, which means the rage/legit aim would shoot through walls at spotted players.

## Defects
- [high] SILENT CROOKED #1, eye position. The eye is the scene-node absOrigin plus viewOffset.z taken at Merge time. That is the interpolated render origin of the local pawn, not the shoot position of the command. The server uses the history entry shoot_position, which the engine computes with GetInterpolatedShootPosition. While the local player moves, the eye is off by up to about 1 tick of movement (around 4u at 250u/s). At close range that is a degree or more of angular error, so silent shots land beside the point. (src/game.cpp:699-712; src/ragebot.cpp:468) fix: Run engine prediction (owner prediction_* sigs) first, then use get_interpolated_shoot_position for the attack subtick, or at least the predicted origin plus the view offset.
- [high] SILENT CROOKED #2, angles are written after CreateMove. OnCmd edits base->viewangles, buttons and history entries after the original CreateMove has already built the cmd. Nothing recomputes the base cmd move_crc. The only call is the opaque mem::Call<void,6>(input, cmd), whose purpose is unknown. If the server or the CRC check rejects or ignores mismatched fields, the shot uses the original angles. Client-side prediction has also already simulated the shot with the original angles, so the client tracer and impact go to the crosshair. That looks 'crooked' even when the server hit lands. (src/ragebot.cpp:587-597; src/core/usercmd.cpp:66-87; src/movement.cpp:382-389) fix: Write angles inside the cmd build path (before CRC and serialization), or call serialize_move_crc afterwards. Find out what vfunc 6 is. Use parse_report_hit to check server hits.
- [high] SILENT CROOKED #3, attack subtick versus history entry mismatch. Click inserts the attack press at when=0.0 (start of the tick), and usercmd::Attack sets attack1=0 only when it was unset. All history entries get one angle, computed from the bones and eye of the LAST frame. Each history entry carries its own render tick/fraction and shoot position, and the server lag-compensates to the entry referenced by attack1, which here is the first frame of the tick. Against a moving target, the target position at entry 0 differs from the bones that were aimed at. (src/ragebot.cpp:426-435; src/core/usercmd.cpp:50-54) fix: Fire on the last subtick (when close to the last frame) and point attack1 at the last history entry. Better, compute the angle per the attack entry's shoot position and interp. Allocate the entry with history_field_alloc when it is missing.
- [high] SILENT CROOKED #4, subtick moves are not compensated. The movement fix rotates only base forward/left. The subtick move steps (analog forward/left deltas and key presses with when) in base->subtick_moves are untouched. The SubtickStrafe/Autostrafe code ran earlier in the same Merge and baked per-event yaws (movement.cpp:311-328). When silent overwrites every history angle with the aim yaw, movement on fire ticks follows the aim yaw: you get drift or slowdown, and strafes break. The reference airstrafe/test_strafer skip work when g_rage.is_firing_this_tick(). (src/core/usercmd.cpp:79-85; src/movement.cpp:427-432) fix: Add an interlock: movement checks rage.is_firing_this_tick, and rage runs before strafers or vetoes them. Rotate the subtick analog deltas too.
- [high] NON-SILENT CROOKED: attack event angle is wrong. Click() runs BEFORE Rotate(). Insert() copies the pitch/yaw of the neighbouring event (or in->pitch) into the new attack event at when=0. Rotate then shifts every event by (target - in->pitch), where in->pitch is the angle at the END of the frame. The attack event therefore ends up at target + (firstEventAngle - finalAngle), so any mouse movement inside the tick goes straight into the shot. (src/ragebot.cpp:437-447,489-497; src/input.h:54-72) fix: Set the attack event's pitch/yaw to the exact target, absolutely and not as a delta, and set all events at or after the shot to the target.
- [high] WRONG CMD CAPTURED (plausible). hkGetUserCmd keeps the FIRST cmd returned on the CreateMove thread. If CreateMove or prediction calls GetUserCmd for an older sequence first, for example when re-predicting, OnCmd edits a command that was already sent or the wrong one. Silent then randomly fails. (src/movement.cpp:435-441,463-472) fix: Get the cmd for the current sequence directly (owner get_usercmd/get_usercmd_base). Do not rely on the first call.
- [high] PREDICTION IS CONCEPTUALLY WRONG. The boxes are extrapolated by velocity*lead, where lead = wall time since the last FrameStage 7 (0-100 ms) plus extraTicks/64. CS2 lag compensation rewinds to the client's interpolated render time, sent per history entry, so the rendered bones are already what the server checks. Extrapolating moves the aim AHEAD of what the server rewinds to. The faster the target, the bigger the miss. The lead also depends on FPS and timing jitter. (src/ragebot.cpp:284-289,331-337) fix: Drop the extrapolation. Aim at the interpolated bones of the attack history entry. Use get_interp_amount and global_vars for any real interp correction, and extrapolate only for packet loss or dormancy.
- [medium] Velocity estimate is noisy. It is an EMA (0.5) of origin deltas between FrameStage-7 calls, divided by QPC wall time and not by tick or interp time. Interpolated origins step unevenly between frames, so dt does not match the movement. Teleport filter: more than 1024u per frame.
